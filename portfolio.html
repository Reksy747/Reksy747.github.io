Pegipegi · Nov 2021 – Jan 2023

Right-sizing Kubernetes on AWS

AWS · Kubernetes · spot VMs · taints · autoscaling · CronJobs · resource tagging

Context
Application products ran on Kubernetes clusters on AWS, alongside GCP. Cluster resources needed to match real demand, and spend needed to be attributable.
What I did
  • Researched and implemented spot VMs on the AWS clusters, with taints to control which workloads run on them.
  • Implemented autoscaling and moved scheduled work to Kubernetes CronJobs.
  • Optimized cluster resources.
  • Wrote a tagging script to tag every AWS resource.
Why it matters
Spot capacity and autoscaling are the main levers on Kubernetes compute cost, and consistent tags are what make cloud cost visible per resource.

Troubleshooting

Troubleshooting complex production issues is the part of the job I enjoy most. This is how I work an incident, from first signal to the change that stops it coming back.

From alert to prevention

Scope
Infrastructure and application issues
Tools
Monitoring, logging, New Relic
Output
Root cause analysis
  1. Detect

    Monitoring and alerting catch the problem, ideally before users do: uptime checks, SLA dashboards, and notifications on critical endpoints.

  2. Diagnose

    Work from the symptom through the stack (DNS, load balancer, NGINX, certificates, the service and its host), using metrics and logs to rule layers out.

  3. Restore

    Get service back first, while keeping the evidence needed to find the cause.

  4. Prevent

    Write up the root cause and turn the fix into something durable: an alert, an automated check, or a script that removes the manual step.
