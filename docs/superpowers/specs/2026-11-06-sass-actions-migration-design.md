# Replace Gulp with the sass CLI and deploy through GitHub Actions: design

Date: 2026-11-06. Status: design approved in chat, awaiting written-spec review.
Base: `master` at `add9471` (the local `vite` branch was fast-forwarded to it; no commits of its own).

## Goal

Remove Gulp and its plugins, build the site in GitHub Actions, and stop committing generated files, so "forgot to rebuild" drift and stale compiled output cannot reach the live site. Keep the site's behavior, URLs and dependencies minimal.

## Decisions already made

- **Option A** from the 2026-11-06 stack analysis: the `sass` CLI plus a GitHub Actions deploy. Not Vite, not Bun.
- npm stays the package manager. Tests stay on `node --test`.
- GitHub Pages stays a user site served at `/`. URLs `/`, `/cv.html` and `/portfolio.html` do not change.
- Drop autoprefixer. Measured on `master`: it adds 5 lines in total (`::-moz-selection`, `-o-object-fit` twice, `-moz-column-break-inside`, `-webkit-text-decoration`), all obsolete.
- Ship `js/scripts.js` unminified (4.4 KB, against 2.3 KB minified). Delete `js/scripts.min.js`.
- No hashed filenames. GitHub Pages sends `Cache-Control: max-age=600` on every file and it cannot be changed, so hashing gives no long-lived caching and risks 404s for visitors holding stale HTML.
- `VERSION` in `sw.js` is stamped at build time from a content hash of every file in `dist/` except `sw.js` (paths included), so nobody bumps it by hand and no cached file can go stale.
- The hand-written service worker stays. No Workbox, no `vite-plugin-pwa`.
- Nothing is committed or pushed by the assistant. The owner commits, pushes and changes the Pages source setting.

## 2. npm scripts

```json
"scripts": {
  "dev:css": "sass --watch --no-source-map scss/styles.scss:css/styles.css scss/terminal.scss:css/terminal.css",
  "build:css": "sass --no-source-map --style=compressed scss/styles.scss:css/styles.css scss/terminal.scss:css/terminal.css",
  "build": "npm run build:css && node scripts/build.mjs",
  "test": "node --test \"tests/*.test.mjs\""
}
```

The `watch` script goes away. Local preview is unchanged: any static server from the repository root, as the README already describes. There is no live reload.

## 3. `scripts/build.mjs`

Plain Node 22, no dependencies. When run directly it builds `dist/`; when imported (by the test) it only exports functions.

Exports:

- `precacheUrls(swSource: string) → string[]`: reads the entries of `const PRECACHE = [ ... ]` in `sw.js`.
- `contentHash(buffers: Buffer[]) → string`: SHA-1 over the buffers in order, first 8 hex characters.
- `stampVersion(swSource: string, hash: string) → string`: replaces the value in `const VERSION = '...';` with `hash`. Throws an `Error` with a clear message if the line is missing.
- `distHash(dir: string) → string`: `contentHash` of every file under `dir` except the top-level `sw.js`, in sorted path order, each file's relative path hashed before its contents. Any changed, added, removed or renamed served file changes the version.
- `isDirectRun(metaUrl: string, argv1: string | undefined) → boolean`: true when `metaUrl` is the script node was started with, comparing real paths (`fs.realpathSync.native`), so symlinks, junctions, `subst` drives and drive-letter case cannot turn a direct run into a silent no-op.

When run directly:

1. Delete `dist/` and recreate it.
2. Copy with `fs.cpSync`: `index.html`, `cv.html`, `portfolio.html`, `favicon.ico`, `manifest.webmanifest`, `sw.js`, `css/`, `js/` (skipping `js/terminal/package.json`, which only the Node tests need), `fonts/`, `images/`. If `CNAME` exists, copy it too.
3. Check that every URL from `precacheUrls` exists in `dist/` (`'/'` maps to `index.html`), failing with its name if not. Then write `stampVersion(sw, distHash(dist))` back to `dist/sw.js`.
4. Print the file count and the stamped version.

`css/` must already exist, so `npm run build` runs `build:css` first. If a precached file is missing, the script fails and names it. The repository's own `sw.js` keeps its hand-written `VERSION`, so local previews and the Node tests are unaffected.

## 4. `scripts/check-dist.mjs`

Run after `build` in CI. It exits non-zero, listing every problem, when:

- a URL in the `PRECACHE` list of `dist/sw.js` has no matching file in `dist/`, or
- a local `href`, `src` or `srcset` URL in `dist/index.html`, `dist/cv.html` or `dist/portfolio.html`, an icon `src` in `dist/manifest.webmanifest`, or a `url(...)` in any `dist/**/*.css` does not resolve to a file in `dist/`.

It reads double-quoted, single-quoted and unquoted attributes (not `data-href`), decodes percent-encoding, and ignores `http(s):`, `mailto:`, `tel:`, `javascript:`, `data:`, protocol-relative URLs and pure `#fragment` links; it strips query strings and fragments; paths starting with `/` resolve against `dist/`, other paths against the page's own folder; a path ending in `/` resolves to its `index.html`.

## 6. CI: `.github/workflows/deploy.yml`

Triggers: `push` to `master`, `pull_request`, `workflow_dispatch`. Workflow permissions are `contents: read` only; the `deploy` job alone adds `pages: write` and `id-token: write`. Concurrency is set per job, not for the whole workflow, because pull-request runs share the workflow and must never cancel a deploy in progress: `build` uses group `build-${{ github.ref }}` with `cancel-in-progress: true`; `deploy` uses group `pages` with `cancel-in-progress: false`.

Two jobs, because the `github-pages` environment only accepts deployments from `master`:

**`build`** (every trigger), on `ubuntu-latest`, Node 22 with the npm cache:

1. `actions/checkout`
2. Fail on conflict markers: run `git grep` for the two marker patterns and treat its exit code 1 (no match) as the only pass. Markers found (0) or a `git grep` error (anything else) fail the build.
3. `npm ci`
4. `npm test`
5. `npm run build`
6. `node scripts/check-dist.mjs`
7. `actions/upload-pages-artifact` with `path: dist`, only on `push` to `master` or a manual run (`workflow_dispatch`) on `master`. `actions/configure-pages` is not used: its outputs are not needed for a plain static site, and the permission it needs on a job without Pages access is undocumented

**`deploy`** (`needs: build`, only on `push` to `master` or a manual run on `master`): `environment: github-pages` with the page URL output, then `actions/deploy-pages`.

Actions are pinned to commit SHAs. At the time of writing, Vite's official guide uses `actions/checkout` v7.0.1 (`3d3c42e5aac5ba805825da76410c181273ba90b1`), `actions/setup-node` v7.1.0 (`949feb2413d6458794dcd2491c4babbbce0c15c1`), `actions/upload-pages-artifact` v5.0.0 (`fc324d3547104276b827a68afc52ff2a11cc49c9`) and `actions/deploy-pages` v5.0.1 (`368f82528645a54fb793d4d04e342629a3f51346`). Re-check them when implementing.

`.github/dependabot.yml` gains a `github-actions` ecosystem (weekly), next to the existing `npm` one, so pinned actions keep receiving updates.

## 7. Cutover and rollback

Two merges, so the site can always be rolled back.

**Merge 1:** build scripts, `scripts/` files, the new test, the workflow, the HTML and `sw.js` edits, deletion of `gulpfile.js` and `js/scripts.min.js`, dependency removal, docs, `dist/` added to `.gitignore`. `css/` stays committed (rebuilt with `npm run build:css`; it differs from today's file only by the 5 dropped prefix lines). Pages stays on "Deploy from branch", so the site keeps serving. The `deploy` job will probably fail until the source is switched; that shows as a red run on `master` and is expected.

**Owner step:** Settings, Pages, Source, "GitHub Actions". Re-run the workflow. Check the live site: terminal, CV, portfolio, offline mode.

**Merge 2:** `git rm --cached` on `css/` and add `css/` to `.gitignore`. After this the site depends on CI having built the CSS.

**Rollback:** before merge 2, switch the Pages source back to "Deploy from branch" (the committed `css/` still serves). After merge 2, revert merge 2 first, then switch the source back.

## 8. Service worker and returning visitors

`/sw.js` keeps its URL, so existing visitors update in place. HTML, JS and CSS are fetched network-first, so they pick up new files; the new content-hash `VERSION` makes `activate` delete the old cache. The hash changes whenever any file in `dist/` changes (except `sw.js` itself), so icons and other files cached on first use are never stale. Returning visitors re-download the precached set after most deploys; it is 19 files, about 282 KB.

## 9. Testing

- The 38 existing tests are unchanged.
- `tests/build.test.mjs` covers the pure functions in `scripts/build.mjs`:
  - `stampVersion` replaces `'v2'` with the given hash and leaves the rest of the source byte-identical.
  - `stampVersion` throws when there is no `VERSION` line.
  - `precacheUrls` returns the entries of a sample `PRECACHE` array.
  - `contentHash` is stable for the same input and changes when any buffer changes.
  - `distHash` changes when any file except `sw.js` changes or is renamed, and ignores `sw.js`.
  - `isDirectRun` compares real paths, not spellings.
- `tests/check-dist.test.mjs` covers the pure helpers in `scripts/check-dist.mjs`: `extractRefs` (quote styles, `srcset`, no `data-href`), `localTarget` (ignored schemes, resolution, percent-decoding) and `cssUrls`.
- `check-dist.mjs` itself is the integration check and runs in CI.
- After implementation: `npm test`, `npm run build` locally, open `dist/` through a static server, and confirm the three pages and offline mode.

## Out of scope
